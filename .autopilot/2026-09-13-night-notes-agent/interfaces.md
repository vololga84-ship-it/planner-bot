# Границы

Ярус T0 — один контекст, без волн. Ниже — проектные правила и швы из
спецификации, без изобретения новых.

## Стек и команды

- Python 3.13, `python-telegram-bot==20.7`, `requests` для Groq HTTP API,
  `gspread` для Google Sheets. Никаких новых зависимостей — всё уже в
  `requirements.txt`.
- Запуск: `python bot.py` (из `D:\Мой планнер\planner_bot`). Тестовой
  обвязки (pytest и т.п.) в репозитории нет — не заводить ради этой сборки
  (см. спецификацию, §Швы).
- Секреты — уже существующий `GROQ_API_KEY` из `.env`/Railway. Новых
  переменных не добавлять.

## Границы, решённые в спецификации

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `notes_sheet` (расширение существующих функций) | чтение/запись листа «📝 Заметки» | `get_new_notes_by_owner() -> dict[owner, list[(sort_key: datetime, row: int, text: str)]]` (отсортировано по Дате/Времени по возрастанию — `sort_key` возвращается, чтобы вызывающий код мог резать по времени без повторного разбора даты), `mark_notes_processed(rows: list[int])` | структуру листа, лимиты Google Sheets API |
| `night_agent` | логика ночного задания | `run_nightly_job(context)` — коллбек `job_queue.run_daily` | порядок «модель → отправка → пометка», разбиение длинных сообщений |
| `llm_structurer` | обращение к модели | `structure_notes_for_owner(owner: str, notes: list[str]) -> str \| None` | какая модель/провайдер сейчас (Groq `openai/gpt-oss-120b`) |

## Шов для проверки

`structure_notes_for_owner` — подменяется заглушкой в автономной проверке
`run_nightly_job` (по образцу уже сделанных в этом файле проверок
маршрутизации режимов заметок), вместе с поддельными Telegram/Sheets
вызовами. Реальный вызов Groq проверяется отдельно, вручную, один раз.

## Что нельзя трогать

- Существующую логику задач/привычек/целей (`process_text`, `parse_task`,
  `handle_text`/`handle_voice` вне новых веток) — не переписывать заново.
- Названия листов «💡 Идеи для постов» — не путать с «📝 Заметки», это
  разные обработки (первый — вручную через content-agent, второй — эта
  сборка).

## Отсутствующая зависимость

Если модель `openai/gpt-oss-120b` вдруг окажется недоступна в Groq на
момент сборки — это `BLOCKED`, не повод тихо взять другую модель без
пометки в отчёте.
